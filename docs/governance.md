# Governance

This document defines how decisions are made in CIVWATCH.

## Principles
- Transparency, inclusivity, and consensus-seeking
- Meritocratic with clear stewardship and RFC process

## Roles
- Maintainers: final reviewers, release management, security triage
- Contributors: propose changes via PRs/issues, participate in reviews
- Steering Group (initially maintainers): resolves stalemates, strategy alignment

## Decision Process
1. Small changes: normal PR + 1 maintainer approval
2. Medium changes: PR + design note referencing an issue; 2 approvals
3. Large changes: RFC in docs/architecture or ADR; discussion for 7 days; 2+ maintainer approvals

## Meetings and Communication
- Async-first via GitHub Issues/PRs
- Monthly roadmap sync notes in repo
- Discord for informal discussion; decisions must be reflected in issues/PRs

## Release Policy
- Semantic versioning; release notes per minor/major
- Security fixes receive patch releases

## Conflict Resolution
- Try to reach consensus; if blocked, Steering Group decides
- Code of Conduct violations handled per CODE_OF_CONDUCT.md

## Voting
- Simple majority of maintainers when needed; tie-break by Steering Group chair

## Amendments
- Changes to this document require PR and majority maintainer approval
