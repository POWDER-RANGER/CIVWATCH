Part I
Web-Based · Self-Paced

Full-stack civic intelligence platform. Self-paced model: user-driven workflows, batch-capable ingestion, async ML processing. Real-time (WebSocket) available but not mandatory UX axis. Deployable via Docker Compose on any VPS; Electron wraps for desktop.

Layer Stack

01 Presentation React 18 + Vite 5 · VEIL Dashboard · Leaflet maps · WebSocket client (optional) · TanStack Query for server state
02 API Gateway Nginx — SSL termination, reverse proxy, static asset serve, rate limiting (limit_req_zone)
03 Application Express.js / TypeScript · Node 20 · REST + WebSocket (socket.io) · Bull job queues · node-cron scheduler · JWT middleware
04 ML Service FastAPI / Python 3.11 · DBSCAN anomaly · HuggingFace sentiment/NER · Promise-action scorer · Celery async workers
05 Ingestion Pipeline Node/Python scrapers · FEC, dispatch logs, contracts/bids, citizen intake · Bull queue-backed · retry + dead-letter
06 Data Layer PostgreSQL 16 (primary) · Redis 7 (cache + pub/sub + session) · MinIO or local FS (documents, evidence, exports)
07 Infrastructure Docker Compose (7 services) · Nginx · Certbot (Let's Encrypt) · Electron (optional desktop wrapper)

ML Service — FastAPI

POST /analyze/anomaly
  body:  { data: float[][], eps: float, min_samples: int }
  resp:  { labels: int[], n_clusters: int, noise_indices: int[] }
  impl:  sklearn DBSCAN; caller passes normalized feature matrix
         (columns: lat, lng, severity, hour_of_day, frequency)

POST /analyze/sentiment
  body:  { text: str, source: str }
  resp:  { score: float, label: "positive"|"neutral"|"negative",
           confidence: float }
  impl:  cardiffnlp/twitter-roberta-base-sentiment (HuggingFace)
         cached in Redis 1h by sha256(text)

POST /analyze/ner
  body:  { text: str }
  resp:  { entities: [{ text, label, start, end }] }
  impl:  spaCy en_core_web_trf; labels: PERSON, ORG, GPE, DATE, MONEY

POST /score/promise-action
  body:  { promise_text: str, actions: [{ description, date, evidence_url }] }
  resp:  { score: float,      # 0.0–1.0
           matched: int, unmatched: int,
           detail: [{ promise_fragment, matched_action|null, confidence }] }
  impl:  sentence-transformers/all-MiniLM-L6-v2 cosine similarity;
         threshold 0.72 for match

GET  /health   → { status: "ok", models_loaded: bool }
GET  /metrics  → Prometheus text format

Alert Dispatch Chain

Rule evaluation loop (every 60s via node-cron)

1. SELECT active alert_rules
2. For each rule:
   a. Evaluate conditions against:
      - Redis pub/sub stream (real-time events)
      - PostgreSQL window query (aggregated thresholds)
   b. condition match → enqueue civwatch:alerts/dispatch-notification

3. Dispatch job resolves channel:
   ├── "email"    → nodemailer → SMTP/SES
   │                payload: { subject, body_html, event_detail }
   ├── "webhook"  → axios.post(user.channel_config.url, payload)
   │                retry 3x, HMAC-signed body
   ├── "in-app"   → socket.io emit to room "user:{user_id}"
   │                → frontend toast + badge increment
   └── "sms"      → Twilio (opt-in, requires TWILIO_* env vars)

4. Write to audit_log (action="alert_dispatched", target=alert_rule_id)
5. UPDATE alert_rules SET last_triggered = now() WHERE id = ...

WebSocket room model:
  user connects → join("user:{user_id}")  [authenticated via token]
  admin connects → join("admin")
  events emitted: "alert:new", "event:ingested", "job:complete"

Auth & Security Controls

Authentication
JWT + Refresh Token
Access: 15 min, Bearer. Refresh: 7d, httpOnly Secure cookie. Rotation on use. bcrypt cost 12 for passwords.
Transport
Nginx TLS + Helmet.js
TLS 1.2+ only. HSTS, X-Frame-Options, CSP header. CORS: explicit allowlist only.
Rate Limiting
Per-IP + Per-User
express-rate-limit: 100 req/15 min global. Auth endpoints: 10 req/15 min. Ingestion API: 500 req/min (keyed).
DB Queries
Parameterized Only
Knex.js query builder; zero raw string interpolation. Input validated via Zod schemas at route layer before any DB call.
Secrets
Env Vars — No Exceptions
JWT_SECRET, DB_URL, REDIS_URL, API keys: env only. .env never committed. Docker secrets or Vault for production.
Audit
Full Audit Log
Every auth event, admin action, report status change, and alert trigger written to audit_log with IP and timestamp.

Offline Sync Protocol

Triggered: network state change (NetInfo) + background fetch (expo-background-fetch)

PULL (server → device)
1. GET /api/v1/mobile/sync?since={last_sync_ts}
   → server returns delta:
     { events: [], officials: [], alerts: [], map_layers: {} }
2. Upsert each entity into corresponding SQLite table
3. UPDATE app_config SET value=now() WHERE key='last_sync_ts'

PUSH (device → server)
1. SELECT * FROM pending_sync ORDER BY created_at ASC
2. For each row:
   a. axios[method](endpoint, JSON.parse(payload_json))
   b. HTTP 2xx  → DELETE FROM pending_sync WHERE id=...
   c. HTTP 4xx  → UPDATE last_error, mark failed (surface in Settings)
   d. HTTP 5xx  → UPDATE retry_count += 1
                  if retry_count >= 5 → mark failed
3. On all clear → emit "sync:complete" event → refresh React Query cache

Conflict resolution
  Server wins on pull (upsert by server ID, server timestamp authoritative)
  Device wins on push (server validates and either accepts or rejects with 4xx)
  No merge: last-write-wins model. Conflicts exposed in UI if push returns 409.

RF Bridge — Android / ADB

# Integrates civwatch-cell-titan scan output into CIVWATCH event schema

Architecture
  civwatch-cell-titan process (ADB / USB serial device)
    ↓ stdout: newline-delimited JSON scan events
  RFBridgeModule (React Native native module OR exec wrapper)
    ↓ parses + validates scan events
  RFEventNormalizer
    ↓ maps to CivWatch event schema
  → POST /api/v1/events  (if online)
    OR insert pending_sync  (if offline)

Scan event schema (cell-titan output)
{
  "scan_type": "cellular|wifi|bluetooth|d2d",
  "anomaly":   "imsi_catcher|rogue_ap|airtag|signal_drop|cipher_downgrade",
  "arfcn":     number,     // corrected EARFCN per v2.0 calibration fix
  "rssi":      number,
  "band":      string,
  "location":  { "lat": number, "lng": number },
  "raw":       string,
  "timestamp": "ISO8601"
}

Normalized CivWatch event
{
  type:     "rf_anomaly",
  source:   "cell_titan_v2",
  location: { lat, lng },
  severity: mapAnomalyToSeverity(anomaly),  // 0-4
  raw_data: { ...original_scan_event },
  tags:     [anomaly, scan_type, "rf"]
}

Implementation options (ranked by complexity)
1. expo-modules-core native module → cleanest long-running bridge
2. react-native-execroot (rooted device ADB shell + stdout pipe)
3. HTTP polling: cell-titan exposes local :8888 REST API, app polls

Feature flag: RF_BRIDGE_ENABLED = Platform.OS === "android" && ENABLE_RF_BRIDGE
UI: hidden tab on non-Android or when flag false

Build & Release
Local:    npx expo build:android --type apk      // debug/testing
EAS:      eas build --platform android           // AAB for store or APK

Distribution:
  Primary:  GitHub Releases (APK) — self-hosted, no store required
  Alt:      F-Droid (FOSS track, requires reproducible build)
  Optional: Google Play (AAB, requires signing config + privacy policy)

OTA Updates (JS-only changes):
  expo-updates → EAS Update or self-hosted update server
  No rebuild required for: UI changes, API URL updates, logic fixes
  Rebuild required: native module changes, SDK upgrades, permission adds

CI Sketch
  push to main → GitHub Actions:
    1. expo doctor
    2. npx expo export (web bundle)
    3. eas build (Android APK) → upload to GH Release
    4. eas update (OTA JS bundle push)
